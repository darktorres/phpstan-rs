**Causes in the code:**
1. A held unit forks one child per other method M2 and each rebuilds the object and re-runs M1. Measured: that is **not** where the time goes (4 %), and nothing hung; the cost is the count of forks, of which 34 % stand behind a constructor that always throws and 34 % behind a probe the object released.
2. Children inherit stdin/stderr (a `STDIN` read could block to the alarm; Imagick/other extensions may write to stderr): hardening, not measured.
3. All probes of a worker share one working directory: files one leaves change what later ones see.
4. No resource limits: the recorder calls every file, stream and image function uncapped (a user disk quota was exhausted earlier in this session; its cause was not established).
5. Progress is units over total; a killed run leaves `/tmp/builtin-runs-<pid>` (six now) and orphaned children (a plain kill of a child leaves what it spawned: measured).
6. No way to re-record some families into the committed table, no record of what the table was recorded with, nothing relating it to what the engine declares.

## Design

### Layout
`record.php` is the entry (arguments, sandbox launch, orchestration). The rest moves to `tools/builtin-runs/lib/`, loaded with `require_once`, so tests load it without running a recording: `seen.php`, `probes.php`, `plan.php`, `child.php`, `unit.php` (the probe of a function, a method, a held unit), `survey.php`, `pool.php`, `sandbox.php`, `cache.php`, `table.php`, `stats.php`. Tests in `tools/builtin-runs/tests/`. Arguments stay compatible: first non-`--` argument is the PCRE (with delimiters, matched on the lowercased builtin name), `--jobs=N`.

### Children and supervision (`child.php`, `plan.php`)
**Flat children, exactly the committed structure.** `spawn(Closure, fds)` forks, `posix_setpgid(0, 0)`, runs the body under `ob_start` and the 3 s alarm, closes the worker's protocol streams (fds 3 and 4) and the other workers' sockets first, sends `serialize($entries)` on a socket pair, ends with `posix_kill(getpid(), SIGKILL)`. `collect(Child, seconds)` waits with `stream_select`, **kills the process group with SIGKILL at the deadline** (a child that overrides SIGALRM or sits in an uninterruptible call still dies; measured: the group kill removes a spawned `sleep`, a plain kill leaves it), reaps, returns `Ok | TimedOut | Died` with wall time. `unserialize` keeps `allowed_classes => false`. A held leaf is a child that constructs, runs M1 and M2 as today (own fds, own state: no sharing between siblings); the survey and the leaf call **one shared function** for "construct, make the probe, run M1 with its arguments inside the `try`", in the old order, so they cannot drift. **Workers stay lean, as a measured requirement** (a heap that has ever been large makes every later fork 100× dearer, see Context): planning and the unit list live only in the orchestrator, a worker is a fresh PHP that receives one unit at a time with its class's slice of the phase-A set and never builds a large structure (survey results and entries are small); each worker reports `memory_get_peak_usage` and its per-child fork time in `--stats`, and the run **warns when a worker's peak exceeds 32 MB**. The orchestrator's own `proc_open` forks are few (workers, respawns), so its large heap does not matter. **Workers run with `USE_ZEND_ALLOC=0`** (measured 2× with identical output on ten families, and 3.4× together with lean workers): it also removes `memory_limit`, so a probe's memory is bounded by `RLIMIT_AS` (2 GiB) instead, and the worker is started with an explicit `memory_limit` so the choice does not depend on the host's ini; the equality of step 10 is the check on the full table, `--zend-mm` switches the allocator back for comparison. **A worker that dies** (killed, OOM, `bwrap` gone) has its unit re-queued once on a respawned worker; a second death marks the unit failed, lists it in the coverage report and makes the run exit non-zero (the committed script drops the unit silently and carries on with fewer workers). At start each worker reports its loaded extensions and FFI availability; a mismatch with the orchestrator (a `PHP_INI_SCAN_DIR` the cleared environment loses) aborts the run. Function and method units are unchanged in structure. `wanted` is applied at plan time (a unit with no wanted M2 is not planned).

**Why not a fork tree** (construct and M1 once in a prefix, a fork per M2): it saves the 4 % re-run cost and nothing else, since every M2 is still a fork; it would share open file descriptions between sibling leaves (offsets, locks, connections: one leaf's read moves the next leaf's offset), needs a supervisor inside the prefix and a deadline protocol, and changes what the alarm covers. Rejected on the measurement.

### Survey and skipping (`survey.php`)
A **held unit is one work item**: the worker forks one **survey child** (class, M1, parameter, probe): build the plain object, run M1 with the probe (exception caught, as today), then report `{released?, wall}` (no data at all means it threw, died or timed out; the parent's deadline is the child's 3 s alarm plus 0.5 s, so the alarm's own death is the normal path, as in the committed script). The worker then runs the unit's leaves itself, with no round trip (at most ~260 leaves, ~2 s: the committed script's granularity, so the tail is unchanged). The unit message carries the slice of the phase-A `probed` set for that class, not the whole set. The decision:
- **dead:** the constructor throws/returns null/dies, or M1 times out or dies (confirmed by the quiet-phase retry) → no leaves. Exact: every old leaf stops at the same statement and records nothing. Costs one survey fork where the old structure paid N (RedisCluster: 1,067 surveys instead of 242,209 forks).
- **released:** `object`/`iterator`/`sleeper`/`callable` probes and `objects`/`callables` arrays, where after M1 the child drops its references (value, arguments, result, exception), runs `gc_collect_cycles()` and every `WeakReference` taken before the call is empty → the object holds nothing of the probe, so no M2 can run it. Leaves are skipped **only if the M2 builtin already has a `probed` row from phase A** (so the `probed` rows stay exact). **`stream` probes** use the same rule with another witness: the recording wrapper counts `stream_close` calls in a counter of its own (not an entry), and the stream was released iff, after the references are dropped and `gc_collect_cycles()` ran, its close was counted (checked: a userland stream is closed when its last holder goes, and stays open while an array, an `ArrayObject` or a context option holds it; a stream filter does not hold it). **Never applied to `url` and `urls`:** a string copied inside an extension cannot be observed, and it matters (`XMLWriter::openUri('rec://probe')` stores it and a later `flush` runs the wrapper: the committed `by:openuri` rows).
- otherwise: all leaves.
`--skip=off|dead|released` (default `released` once step 10 shows the three outputs equal; `off` = the committed structure). **Two-phase scheduling:** phase A = function and method units, yielding the `probed` set; phase B = survey + leaves of held units, the orchestrator sending each worker the set. **Residual risk, stated:** a builtin may keep only a class-level fact of the probe (a class entry, as `ReflectionClass::__construct(object)` does) a clone (the recording objects implement `__clone`) or a serialized copy (`__serialize`/`__unserialize` are recorded too), run later on a fresh instance; the object is then released and its leaves skipped. The recording methods only record when called, so no such row is known; the equality of `off`/`dead`/`released` over the full run (step 10) is the check, and a difference removes pruning for that class, not the feature. Ground truth available: for all 14 (class, M1, parameter) triples behind the committed `by:` rows at least one probe at that parameter is retained or non-prunable (checked), so `released` loses none of them.

### Sandbox and limits (`sandbox.php`, `pool.php`)
- **Two roles.** The **orchestrator** (arguments, planning by reflection, cache, progress, merging, table/sidecar/report writes) runs outside any sandbox. Each **worker** is started by `proc_open` as `bwrap … php -d ffi.enable=1 worker.php` (plain `php` for `--sandbox=none`), protocol on extra pipe descriptors (fd 3 in, fd 4 out; checked: they reach `php` inside `bwrap`), stdin/stdout/stderr = `/dev/null` through the descriptor spec (no `dup2`). Whole-recorder-in-sandbox was rejected: the cache and the table are written by the orchestrator.
- **bwrap line (checked verbatim here):** `--unshare-net --unshare-pid --unshare-uts --unshare-ipc --hostname rec --die-with-parent --new-session --clearenv --setenv PATH … HOME /tmp/work LC_ALL C TZ UTC --ro-bind / / --dev /dev --proc /proc --tmpfs /home --ro-bind <tools/builtin-runs> <same> --size <cap per worker> --tmpfs /tmp --chdir /tmp`. `--size` must come immediately before its `--tmpfs`; the work directory lives **under the capped `/tmp` tmpfs** (a `--tmpfs /work` fails: the root is read-only). Verified inside: the tool directory is readable, `/home` shows an empty `torres`, `~/.ssh` is invisible, hostname `rec`, environment is exactly the five variables, the tmpfs stops at its cap, the probe is pid 2. Needs no root here (AppArmor profile for `bwrap`; `apparmor_restrict_unprivileged_userns=1`; not portable). `--sandbox=bwrap|sudo-unshare|none`, default `bwrap`. **`sudo-unshare` (`sudo -n unshare -n -- sh -c 'ip link set lo up; exec setpriv …'`) is selected only by that flag, never as an automatic fallback** (it escalates privilege). A sandbox that cannot start is a hard error; `none` exists for equality checks and is recorded in the sidecar. Stopping: the orchestrator terminates the `bwrap` processes (`--new-session` takes them out of its process group); `--die-with-parent` covers the orchestrator dying. Worker RAM: each tmpfs counts against memory (cap × jobs), so the cap is `min(256 MiB, MemAvailable / (2 × jobs))`.
- **Skip list:** `SKIPPED` shrinks to what endangers the recorder itself. **Every `pcntl_*` and `posix_*` function stays skipped, as `units()` does today by prefix** (70 functions; the coverage report lists them as `skipped by the recorder`); `dl`, `stream_wrapper_unregister`, `stream_wrapper_restore`, `excimer_set_timeout` stay; the network, process, sleep and mail names leave the list; `readline` and `readline_callback_handler_install` stay (they read the terminal). Network, DNS, mail, process and sleep functions are probed and measured (checked in the net-less sandbox: `exec system passthru shell_exec popen usleep time_nanosleep time_sleep_until mail fsockopen gethostbyname gethostbynamel gethostbyaddr dns_get_record` return in under 20 ms, `sleep(1)` in 1 s). The 20 `RUNS_NOTHING` rows become measured; a function of them that does not complete cleanly keeps its asserted row and is listed as `asserted` in the coverage report.
- **Per-child limits** via the FFI already loaded for `prctl`: `RLIMIT_FSIZE` 64 MiB, `RLIMIT_AS` 2 GiB (PHP's VmSize is 131 MiB), `RLIMIT_CPU` backstop, `RLIMIT_NOFILE`, `RLIMIT_CORE` 0. `SIGXFSZ` ignored in children (measured: with the default action the child is killed by signal 25 mid-call; ignored, the write returns short and the next fails with EFBIG). **No `RLIMIT_NPROC`** (counts all of the user's processes: 141, limit 80,785). No FFI: the run refuses to start.
- **Directories:** a fresh directory per top-level child on the worker's tmpfs, **seeded with one non-empty regular file named `x` (`"x\n"`) and nothing else**, removed after the child is reaped (the parent runs `chmod -R u+rwX` then `rm -rf`: a probe may leave a mode-000 directory, and removing with a `RecursiveDirectoryIterator` in the worker killed the worker in the prototype). The seed is the probe environment's declared state: `x` is the generated string probe, and the committed rows `copy 1 wrapper *`, `splfileobject::fputcsv 0[]`, `openssl_pkcs7_encrypt`/`openssl_cms_encrypt 2` and `file_put_contents`' four rows exist only when `x` is a writable non-empty regular file (measured with `x` absent, empty, a directory and non-empty). It replaces an order accident of the old script with a fixed state, so the output no longer depends on the regex or on `--jobs`. Start-up removes stale `/tmp/builtin-runs-*` whose pid is dead (the six present now are such).
- **Load-independent timeouts:** a unit's result lists the children that timed out or died, each as a self-contained spec (unit, probe, M2); after the pool drains, exactly those children are rerun on `max(1, jobs/4)` workers (a quiet machine, not a serial queue: deterministic hangs are expected, 9 in the `ds` family alone, each costing the full 3 s again) with the same timeout; a first-pass value is never replaced; only a child that fails twice is a hang. For a survey the retry is the survey (a dead verdict is only final after it). A unit that failed because its worker died is never cached.
- **Interruption:** the orchestrator handles SIGINT/SIGTERM by stopping its workers, removing its directories and writing nothing. Checked: with `bwrap`, SIGKILL of the orchestrator removes every worker and probe (`--die-with-parent`; php 4→1, bwrap 8→4 processes); with `--sandbox=none` workers survive and leave when their protocol pipe closes, their children by the 3 s alarm.
- **Canary self-test:** before any probe, user-class units with known answers (stores a callable and runs it; ignores it; hangs; exits; constructor throws) run through the same sandbox and survey; a wrong answer aborts.
- **Atomic output** for `--out`/`--update`: table, sidecar and report go to temporary files and are renamed once all are complete.

### Results, cache, provenance (`table.php`, `cache.php`, `stats.php`)
- **`--update=FILE`:** runs only the builtins selected by the regex or by **`--ext=redis,ds,…`** (the extension's names come from `get_extension_funcs` and `ReflectionExtension::getClassNames`; checked: all 1,934 internal functions and 312 internal classes map to a loaded extension), removes the rows of those builtins from FILE (rows are tagged by the called builtin, so this is exact), merges, sorts `SORT_STRING`.
- **`--cache=DIR`** (default `~/.cache/builtin-runs`), per top-level unit; its purpose is **resuming an interrupted run and `--update`**, since any change to the recorder invalidates everything. Key: recorder library hash, `PHP_VERSION`, `PHP_BINARY` size+mtime, for every loaded extension a hash of its `ReflectionExtension::info()` text (carries linked library versions) **except `Core` and `FFI`** (measured: `Core`'s text differs between two identical runs and `FFI`'s with `-d ffi.enable`; every other extension is stable), the unit's reflection signature hash (for held units M1 and M2 too), the sandbox mode, `--skip` mode, and for held units the hash of the phase-A `probed` set that decided skipping. Stored value is the result after the quiet-phase retry. `--no-cache` forces everything; `--verify` ignores the cache.
- **`--verify`:** every top-level child runs twice; reconciled conservatively: `calls`/`method`/`wrapper` kept if seen in either run, `probed`/`releases` kept only if both agree; every unit that differed is listed.
- **Sidecar `builtin-runs-8.5.meta.json`** (beside the table, written only by `--out`/`--update`): SHA-256 of the table it describes, PHP version and build, each loaded extension with version, `info()` hash and provided names, recorder hash, sandbox and skip mode, counts per row kind, and a `runs` list (date, selection, flags, totals, and that run's extension manifest), because a partial update makes the table a mixture; the integrity check uses the union of the manifests (checked: every builtin in the committed table is provided by a currently loaded extension, so the first sidecar satisfies it). Table, sidecar and report are three renames, not jointly atomic; the hash in the sidecar detects a crash between them.
- **`--coverage=FILE`:** every builtin with no `probed` row and why (timeout twice, died, abstract class, constructor refused, skipped by the recorder, filtered), grouped by extension. It reads the engine's own declarations from `crates/stub-sources/index.tsv` (kind, key, extension; the checked-in stub index) and reports, per stub extension, the declared functions and classes with no row, split into *extension not loaded here* and *loaded but no row* (measured now: 3,447 of 5,282 stub functions and 3,035 of 3,168 stub classes have no row, nearly all of them extensions this PHP lacks: libvirt, pdflib, ncurses, fann, uv, oci8, couchbase, cassandra, mongodb, swoole, ...).
- **Observability:** `--list` prints the plan (units and forks per kind, top classes) and exits; progress every 5 s on stderr as percent of planned forks, elapsed, ETA, forks/s, timeouts; `--stats=FILE` JSON lines per child (kind, builtin, where, wall ms, outcome, skip reason) and a summary (wall histogram, slowest units, timeouts by class, forks skipped by reason).
- **Tests wired into cargo:** `crates/phpstan-rs/tests/builtin_runs_recorder.rs` runs `php tools/builtin-runs/tests/run.php`; without `pcntl` it skips with a printed reason, and the sandbox cases alone skip (also printed) when `bwrap` is missing **or fails to start** (an AppArmor-restricted machine has the binary and no permission), the rest run with `--sandbox=none` (precedent: `tests/runtime_oracle.rs` calls `php` and reports `skipped`). The **integrity test** (table hash equals the sidecar's; every `probed` builtin is provided by an extension the sidecar lists) is added in step 12, with the first sidecar, because no sidecar exists for the committed table. **Drift test** (step 12, with the sidecar): the sidecar records the recorder's gaps (`coverage` result); a cargo test reads `stub-sources` `INDEX` (and `builtin_function_extension`/`builtin_class_extension`, `registry/stubs.rs:1295,1304`) and fails when a stub function or class of an extension the sidecar lists as recorded has no row and is not in the sidecar's gap list, i.e. when a stub update or a new extension makes the table stale.

## Intended differences from the committed script (each seen in a diff, not assumed)
- Fresh directories seeded with `x` and `/dev/null` stdio: removes order- and scheduling-dependent rows and keeps the state-dependent ones deterministic (a regex-restricted run now equals the same rows of the full run; measured: the old script's does not).
- Sandbox: network, DNS, mail, process and sleep functions are probed; the 20 asserted rows become measured; env, locale, zone and hostname are fixed.
- Timeouts are retried once in quiet conditions; a unit lost to load is no longer lost.
- `proc_open` gains `0[] method __tostring` and `4[] method __tostring` (measured), and any other row the 20 asserted names yield when measured; the asserted rows were not neutral.
- Limits apply in every worker (also `--sandbox=none`): a call needing more than 2 GiB of address space or writing a file over 64 MiB now fails where it did not. Step 8 and step 10 list any row this changes.
- A held unit whose survey shows a dead constructor or hanging M1 plans no leaves (same output when the failure is deterministic).

## Not done, with the reason
- Fork tree / prefix: refuted by measurement (D1).
- All M2 in one child: calls change state, close or kill the process; results would depend on order.
- Partial entries from a timed-out child: a builtin marked `probed` on a partial record claims "runs nothing" without evidence.
- Pruning `url`/`urls` probes: retention of a copied string is unobservable and matters (committed `by:openuri` rows). A stream-probe prune is included, but no committed row exercises it, so step 10's equality is its only check.
- Lowering the 3 s default: needs a full run at the lower value to be output-identical; the `--stats` histogram will show whether anything is near the ceiling.
- Leaf concurrency inside a unit: a held unit is one work item (P1) of at most ~260 leaves, about 2 s, and units are cost-sorted, so the tail after the last unit starts is at most that; splitting a unit would cost a round trip per leaf and give the survey's verdict to several workers.
- A dedicated zygote process that all workers fork from: unnecessary, a worker started by `proc_open` is already a fresh lean PHP (fork 2.5 ms measured); a zygote would only add a process to supervise.
- Probing more value shapes (the value kinds are the table's grammar; a new kind changes `build.rs` and the engine); per-PHP-version tables (the engine reads one file, `build.rs:188`; `tools/php-images` belongs to master3).
- The unsandboxed old run for timing: reaches the network; not run.
