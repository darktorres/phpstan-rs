## Prerequisites (each section below depends on them)

1. **`EffectIx`: a registry-level dense, `Copy` index of effect ids.** `EffectId` is an enum `{Function(FnId), Method(MethodRef), PropertyHook{..}, Closure{caller: Box<EffectId>, ordinal}, File(FileId), Named(DeclKey)}`, not `Copy`, and `Transfer::Other(Option<Name>)` is `Clone`, not `Copy`. Build `EffectTable { ids: Vec<EffectId>, index: FxHashMap<EffectId, EffectIx> }` once in `resolve_effects`, with both directions (id to `DeclKey` is needed by `by_ref_at`, `passes_arguments`, `passed`, `builtin_runs` and `Site`), plus an interned `Transfer` (`TransferIx(u32)`). The `declaration_effect(key)` fallback that `settled`/`settled_effect` use for a declaration absent from `effects` is kept. The table outlives `settle` (Y and P read it after); I's dense `settle` index is this table, not a second one. Lands with item 3; I reuses it in item 6.
2. **`Name.lowered: OnceLock<Name>`.** `NameData.lower` is an `Option<Box<str>>`, a string, so no lowercase `Name` exists today: every `method_key` interns (`lowered_text`: 2,778,993 calls, 773.7 M self, 1,043.6 M inclusive). Lands in item 2.
3. **No change to the order of any output.** Every memo or shared set keeps the order of the structure it replaces (`BTreeSet<Storage>` order, `sort_ref_keys` order, `OrdMap` key order); where a section changes a container it says what keeps the order.

## A. Summaries are deduplicated by printing them to text (item 1)

**Problem.** 0.92 G exclusive (`Printer::node` 2015 M inclusive, `Callee::canonical` 1983 M, `Origin` 1370 M). `Summarizer::implicit_on` (`summaries.rs:1748`, `scope.implicit.insert(canonical::print(&callee))`, 238,557 calls = 851 M) and the origins filter (line 1140, `seen.insert(canonical::print(origin))`, 37,410 calls = 79 M) build a `String` of the whole callee/origin tree only to use it as a set key.

**Design.** A structural key whose equality equals canonical-text equality (spans included).
- Derive `Hash`/`PartialEq`/`Eq` on `QualifiedName` (`Name`, `ResolvedName`, `Span`), `ResolvedName` (has `PartialEq`/`Eq`, lacks `Hash`), `Access`, `Callee`, `Origin`, `Receiver`, `Place`, `Root`, `Step`, `Operation`, `Narrowing`. `Name` is safe: `Eq` is pointer identity with a debug assertion against text (`name.rs:243-258`), `Hash` writes the stored `u64`.
- A member holding a `Type` is **not** covered by a plain derive: `Type::eq` (`types/src/lib.rs:594-650`) is case-insensitive for `Object`/`EnumCase`/`HasMethod` and order-insensitive for unions, while `canonical_text` of `Foo` and `foo` differ. `Origin::Declared(Type)` and `Narrowing::Declared(Type)` hold a key made of the type's `canonical_text` (a `String` built only for these two rare variants, hashed and compared as text). A node-address key is unsound: interning is by exact form (`intern.rs:465-482`, member order is part of the node) while `canonical_text` sorts union and intersection members, so `A|B` and `B|A` are two nodes that print alike.
- **The set stores no key:** a `hashbrown::HashTable<u32>` holds indices into the vector the item is pushed to (`scope.calls` for `implicit_on`, the output `Vec<Origin>` for the origins filter), hashed structurally and compared against `calls[i].callee`; a duplicate costs one hash and one compare, a new item costs no clone. `implicit_on` builds the key before the `Callee`, so a duplicate builds nothing.
- Narrowing sites (`summaries.rs:2332-2345`): `Vec<Vec<String>>` and the linear `way.contains(&key)` become one `FxHashSet<(Name, NarrowingKey)>` per way.
- `with_capacity` for the scope vectors.

**Oracle.** `debug_assertions` asserts key equality == canonical-text equality on every insert.

## F + G + Prerequisite 2. Names carried end to end (item 2)

**Problem.** `is_folded_eq` 1.38 G over 14.8 M calls and `fold_hash` 0.90 G over 16.3 M, from `name.rs:1370`. Per caller: `Registry::class::<str>` 3.13 M (from `member_slot::<str>` 650 K, `member_entries` 385 K, `Reach::implicit_method` 342 K, `is_subclass_of` 246 K, `methods_named` compute 174 K, checker ~400 K), `Resolve::run` inline 2.25 M, `method_owners::<str>` 1.27 M, `class_references_by_name` 0.91 M, `property_owners::<str>` 0.62 M, `Registry::function` 0.81 M, `lookup_method_with_owner` 1.5 M, `effect_id_for` 356 K, `member_slot::<Name>` 768 K, `lookup_own_method` 7.55 M `is_folded_eq`. `lowered_text` 1.04 G (callers `Registry::reached` 772 K, `Reach::implicit_method` 660 K, `methods_named` compute 606 K, hook compute 260 K, `effect_decl_key` 142 K): it lowercases and interns two strings per `method_key`.

**Design.**
- `DeclKey { class: Option<Name>, member: Name }` holding lowercase `Name`s; delete `decl_hash` and `DeclQuery` once no `&str` probe remains outside API edges. `DeclKey::hash` is a mix of two `folded_hash` values, and `Name::folded_hash` is that same function over text, so a key built from two lowercase `Name`s computes it from the stored hashes with no byte pass; the borrowed `dyn DeclQuery` probes keep hashing identically.
- `Name.lowered: OnceLock<Name>` filled on first use; a name whose `lower` is `None` (already lowercase) returns itself without storing anything (no self-referencing `Arc`); a mixed-case name interns its lowercase `Name` once, kept alive by the original. One `OnceLock<Name>` word per `NameData`.
- `method_key(class: &Name, method: &Name)` builds a key from two pointers. Delete `lowered_text` and its thread-local.
- A `WellKnownNames` struct in a `LazyLock` holds the interned `Name`s (and lowercase forms) of the `&'static str` method names `implicit_methods` passes (`"__toString"`, `"offsetGet"`, `"getIterator"`, …).
- `DeclKey::closure` and `hook_key` still intern one new name per call (15,817 and 144 calls); both run once per declaration.
- `Holder::Classes` already holds `Name`: pass the `Name` to `implementations`, `is_subclass_of`, `declared_holder`, `lookup_method_with_owner`. Give `member_slot`, `method_owners`, `property_owners`, `class_references_by_name`, `function`, `resolve_function`, `lookup_method_with_owner` `Hashed`/`FoldKey` method keys and `TableKey` class keys (as `lookup_own_method` has) so each name is folded once per call chain.
- `DeclKey::new` has 1,160,567 calls (from `Registry::reached` 386 K, `Reach::implicit_method` 330 K, memo `OnceLock` inits 83 K, `call_targets` 135 K, `effect_decl_key` 71 K, none from decoding), so the `DeclKeyNames` serde form is only used by snapshots and stays unchanged.
- `DeclKey::file` formats a `u64` into a `String` (14,303 calls): with `EffectId::File(FileId)` held in the `EffectTable`, the text is built only at API edges.

Largest churn of the batch: `registry/effects.rs`, `registry.rs`, `registry/hierarchy.rs`, `registry/reach_memo.rs`, `checker/call_effects.rs`, the effect tests.

## C + B. Implicit keys, holders (item 4)

**C, `implicit_call_targets`** (4.98 G inclusive at `Resolve::run` line 4177, 582 K calls): memo-miss compute 2914 M for 145 K misses (24 %), `ctx.operand` 1526 M (B), key building ~470 M (`ImplicitKey` built twice per call: `Holder` clone, `scope` lowercased to a new `String`, `OperationKey`), and in `implicit_targets` the unknown-holder branch pushes every cached key one by one (1.87 M pushes = 536 M of `TargetSet::push`). The measured cost of the property path is `implicit_method`: 972.6 M inclusive over 690,661 calls (204 K from `unknown_implicit_keys`, 486 K from `implicit_targets`), each ~2.5 K Ir (`lookup_method_with_owner` 419 M, `lowered_text` 217 M, `method_is_abstract` 159 M, `Registry::class::<str>` 89 M, `DeclKey::new` 49 M). `unknown_implicit_keys` for a property operation is never memoised (`OperationKey(0,..) => compute()`, 679 M over 4.4 K computes).

Design:
1. `implicit_method(class, method)` is a pure function of the registry (`lookup_method_with_owner`, `class`, `method_is_abstract`, `is_magic`): memoised by `(class Name, method)`; `implicit_methods(class, operation)` is pure for every operation except `Operation::Property` (its `property_magic(class, prop, ctx.class(), ctx.rebindable())` reads the scope), so only non-property operations (701,855 calls, 377.7 M) are memoised, keyed `(class Name, operation kind)`; the property operation keeps its scope in the key. `hook_member` (356 K calls, a `String` per call) is memoised by `(property, set)` as a `Name`.
2. Unknown holder: produce the shared `Arc<[…]>` directly instead of pushing, only at the top level, i.e. when the operand's holder is `Unknown`/`Made(None)` at the entry of `implicit_call_targets` (`implicit_targets` recurses for an `IteratorAggregate`'s given iterator with the same `out`, where a class-derived key could equal an unknown-list key). The result is `hooks ++ unknown_list` with one transfer; hook members always begin with `$` (`hook_member`, `effects.rs:609`) and no method name can, so the two parts are disjoint, and each cached list is a set (`compute_unknown_implicit_keys` dedupes through `seen`). Memoised by `(OperationKey, transfer kind, scope when hooks are non-empty)`. Oracle: compare with the pushed result.
3. `ImplicitKey` borrowed-key lookup (`get_or_compute_ref` with a `Hashed` key; scope as an interned lowercase `Name`; `OperationKey` `Copy`), built once per call. `ImplicitKey` hashes a whole `Holder`; with `Arc<[Name]>` (below) that is a slice hash of pointer-identity names, so no holder interning is added.
4. `Level::class` (1.48 M calls) and `Level::rebindable` (1.38 M calls) are constants of the function-like being resolved: `Level` holds them as fields read once per `ImplicitKey`, not once per target.
5. The `implicit_methods` memo init extends a `Vec` into `Arc<[..]>` (57.8 M of `memcpy`): build with exact capacity.

**B, holders** (`operand`/`receiver`/`origin_holder` 668 M exclusive, 790 K calls; the `operand_origin` cache misses 633 K of 790 K). Rounds are not the cause (`Resolve::levels` runs 80,004 times for 78,097 `Resolve::run` calls); each origin is met once per declaration. Of the 755 K computes, `Origin::Place` is 313 K (`value_holder`), method results 292 K, function results 150 K.

Design:
1. `Level` gets `class_name: Option<Name>` and a ready `this_holder: Holder`; `Receiver::This`, `value_holder(Root::This)` and storage code no longer call `Name::from(class)` (interning).
2. Registry memo of `returned_holder` in `ReachMemo`, keyed span-free: `Function` by resolved name; `Method` with a `This`/`ThisProperty`/`Static` receiver by `(class, method)`; `Static` by `(resolved class, method, calling class)`; `ParentHook` by `(property, set, class)`; keyed on `class_name` for the ones that read `self.class`. A `Method` with a `Variable`/`Origins` receiver reads `solved` (partially filled while `solve` runs) and is **not** memoisable (43 % of the calls: 223,343 of 524,489). **Problem.** `Session::parse_listed` marks a file cacheable only when it is a context file (`cacheable: context && !held && !keeps_tree`, `session.rs:1345`), so an analysed file's derived data is recomputed every run. For the 2,792 analysed files `parse_file_recording_with_origin` is 6.13 G inclusive: lexing 894 M, `Parser::parse_program` 1,804 M (the tree, needed), **`FileBodies::collect` 2,592 M** (`BodySummary::summarize` 1,535 M + `of_file` 962 M), **`GlobalFacts::of` 311 M**, **`file_declarations::collect` 292 M**, plus name/reference recording. The 11,459 cacheable files decode the same data for 956 M (bodies) + 652 M (decls) = 140 K Ir per file against 1.15 M Ir computed.

**Design.** Keep `parse_recording` exactly as is (tree, recorder references, `ignores`, lex warnings, facts, line index, `name_anonymous_classes`). Replace only what follows it in `parse_file_recording_with_origin` (`project.rs:4009-4076`: `file_declarations::collect`, `file_references`, the anonymous-class list, `FileBodies::of_file`, `GlobalFacts::of`, `PestFacts::of`) by the cached copy.
- `cacheable` becomes `!held` (not `context && …`); the key is `file_cache::key(bytes, path, is_stub, index_use_sites)` unchanged (no `tree_kept` bit: the entry holds no tree and is identical for the same inputs; the key includes the build's source hash `registry::cache_key()`, so every cache-format change in this plan invalidates old entries by itself, no separate bump anywhere).
- A hit on an analysed file takes `CachedFile::into_parsed` and attaches the freshly parsed `tree` and `ignores` (a new `into_parsed_with_tree`; `into_parsed` returns `tree: None`, `ignores: Default::default()`). `lex_warnings` and `line_index` are in the entry and also produced by `parse_recording`: use the entry's, drop the fresh. Held/overlay files and language-server files keep the compute path.
- The cached `class_fn_refs` is stored after `shared.index_use_sites` ran (`parse_listed` stores last), so a hit already carries it; the analysed path must not run `index_use_sites` a second time.
- Decoded provenance is rebased onto the run's `FileId` by `with_origin_file_id`, as for context files; `Origin::File(FileId)` has no analysed/context distinction and `CachedFile.origin_file_id` is `None` for a file with no class/function declarations.
- Because the tree is re-parsed deterministically from the same bytes, expression and statement ids in cached summaries (`Callee::Include(u32)`, spans) match it. Oracle (`oracle` profile): recompute `file_declarations::collect`, `file_references`, `FileBodies::of_file`, `GlobalFacts::of`, `PestFacts::of` from the tree on every hit and compare with the entry through `Canonical`, including the attached `class_fn_refs`.
- Disk: 2,792 more entries under the 2 GB cap. In off mode (`NO_FILE_CACHE`) AA changes nothing.
- Known gap: a hit still pays `parse_recording`'s `Recorder` work (its references are then discarded for the entry's); that cost is inside the parser figure that stays. A recorder-off parser mode is a follow-up lever once the end-of-batch profile shows the share.

## Instrumentation (item 0b)

One always-on facility, `phpstan_rs::stats`, extending the `syntax::memo::Memo<V>` precedent (`MemoStats { hits, misses }`): a crate-level module with `#[inline]` counters over thread-local `Cell<u64>` arrays indexed by a `Site` enum, merged into a global `AtomicU64` array when a thread exits or on `flush()`; one non-atomic increment per event, no lock, no allocation, compiled in always (the profiled binary is the shipped one). `PHPSTAN_RS_MEMO_STATS=1` prints the merged table to stderr at exit. Sites: Y operations (hit/miss), the `current_class_template_params` memo, B's `returned_holder` memo, C's `implicit_method` memo, the regex-pattern memo, `parse_sql_cached`, the `rejected_from` and `to_string_type` memos (Z), the `descendants`/`template_paths` memos, the `Callee` node table (distinct over total), the vendor autoload cache (hit/miss) with a wall-clock site (`Instant` before and after the join, summed in nanoseconds), and diagnostics dropped per filter stage. **Removal rule:** after the end-of-batch drill, a memo site with a hit rate under about 20 % is removed in a follow-up commit and the ledger records the measured rate for every site, kept or removed.

## Exclusions with a measured reason

- **`ContentHash::of`, the single remaining hash** (~0.03 G over 14,251 files): it is the content-addressed key of the cache and of `Session` change detection. A stat/mtime shortcut is excluded as unsound (a same-size, mtime-preserving rewrite — `rsync -t`, `tar`, composer installs — would be served stale data). Bound 0.07 % of the profile; reopen if a content-hash-free change detection exists.
- **Fusion of `Summarizer` with the other body passes:** its order is part of its meaning; excluded.
- **Recorded-transcript memo for calls (Y):** measured 12 % hit rate; withdrawn. Reopen only if instrumentation after other changes shows a rate above 20 %.
- **Per-thread `rayon::spawn` drops, an off-thread drop of `classified`:** withdrawn (W).
- **Interned `Storage` ids, node-address keys for `Origin`/`Type` sets, a `Type`-keyed address dedupe in `union_many`, eager storing of resolved class results:** withdrawn as unsound (A, Q, Z, L).

## Pitfalls found by validation (each is a constraint on the items above)

- `EffectId` is not `Copy` and `Transfer::Other` is not `Copy`: nothing may assume cheap ids until `EffectIx`/`TransferIx` exist.
- `ClassId` equality includes the generation: any dense table indexed by `local()` stores and compares the full id.
- `call_targets` has side effects through `runs_written`: memos replace lookups only, never the function.
- `Type::eq` is case- and order-insensitive but interning is by exact form, and `canonical_text` sorts members: no address key stands for text equality.
- `Name::cmp` is by text; a shortcut may only add the same-allocation `Equal`.
- `settle` order independence holds only for non-anything entries (see I).
- A `Variable`/`Origins` receiver reads partially filled state: not memoisable in B.
- The `Walker` gate must include named static calls; the `Promotions` gate may skip only the in-body traversal.
- `Locals::variables` iterator holds a `RefCell` borrow: keep a collected form where the caller interns keys or mutates.
- `PerClass::iter()` order is unspecified today; every caller sorts or collects.
- Member-slot iteration by position needs the release-mode uniqueness check (V, L).
- Isolated-registry reset must be an exhaustive destructure (M).
- The cache key is the build's source hash: format changes in this plan need no version bump, but an entry written by an older build must never be read (it is not: different directory).
- An analysed-file cache hit must not run `index_use_sites` again (AA).
